2El sistema de un vistazo

La idea rectora del repositorio: un solo núcleo científico en Python que corre en dos runtimes. El mismo código —el mismo wheel, de hecho— se ejecuta en el servidor FastAPI y dentro del navegador vía Pyodide. El frontend no sabe cuál está usando.

6Los espejos: la zona de peligro

Ésta es la sección que hay que leer antes de tocar el core. Hay lógica duplicada a mano entre Python y TypeScript. Nada avisa cuando se desincroniza, salvo donde existe un test de contrato.

ConceptoOriginal (Python)Espejo (TS)¿Protegido?
Esquema de configuraciónconfig.pylib/types.ts · types-v2.tsParcial — contract.spec.ts compara estructura y defaults
Función de utilidaddemand/utility.pylib/utility.tsNo — sólo alimenta el inspector
Oferta de vivienda S(i)land_use/supply.pylib/citySupply.tsSí — contract.spec.ts con fixture golden
Presetspresets.pylib/presets.tsNo
Los 42 betaspresets.py DEFAULT_STRATAlib/defaults.ts baseBetasNo — hueco conocido y pendiente
Serialización del traceapi/serialization.py:79workers/pyodide.worker.ts:155No — dos gemelos que deben moverse juntos

Las cinco trampas que ya mordieron

  1. El wheel viejo. Tras tocar el core hay que recompilarlo o Pyodide sigue corriendo el código anterior. En esta máquina: uv build --wheel y copiar el .whl a apps/web/public/pyodide/.
  2. Presets con valores absolutos. Declaran valores, no diferencias: al recalibrar un default hay que moverlos, o aplicar una política revierte ese parámetro en silencio. Ya pasó cuatro veces.
  3. Una tercera copia de los betas vivía en un script de auditoría y midió valores viejos sin avisar. Eliminada, pero el patrón vuelve.
  4. model_copy(update=…) de Pydantic no valida: una clave inexistente se cuela como atributo suelto y el barrido reporta «inerte» un parámetro que no se está moviendo. Los scripts llevan un guard.
  5. Sub-objetos anidados. Cualquier recorrido de la configuración que asuma estructura plana se salta penalizaciones_fisicas en silencio. Produjo una falsa anomalía en la auditoría del todo-o-nada.

extra="forbid". Agregar un campo nuevo con default es seguro; quitar o renombrar uno rompe la importación de escenarios .ttrq.json ya guardados y los enlaces ?s=. Es la razón por la que el método determinístico conserva el valor "wardrop" en el esquema.

7Flujo de una simulación, paso a paso

Qué ocurre exactamente cuando el alumno aprieta «Simular equilibrio», con el archivo de cada paso.

#PasoDónde
1Los sliders escriben en el SimulationConfig del storecomponents/modules/* → store/simulationStore.ts
2startRun elige motor: local (default) o apistore/simulationStore.ts:51
3La config se serializa y cruza al Web Workerlib/pyodide-engine.ts → workers/pyodide.worker.ts
4Pydantic valida y construye la ciudadconfig.py:311 → city.py:15
5Se resuelve el uso de suelo y de ahí sale la poblaciónland_use/ciudad.py:41 → population.py:155
6Los agentes se agrupan en (estrato, celda, auto)equilibrium/msa.py:122
7Iteración: cada grupo calcula utilidades…demand/utility.py:60
8…y se reparte según el método elegidodemand/choice.py:19 · 44 · 100
9La demanda resultante entra a las tres ofertassupply/car.py:36 · bike.py:32 · train.py:34
10Los tiempos nuevos se promedian con el paso 1/(it+1)equilibrium/msa.py:363
11Se emite un IterationSnapshot y se evalúa el residuoequilibrium/msa.py:41
12El snapshot se serializa y vuelve al hilo principalworkers/pyodide.worker.ts:155
13pushIteration actualiza el store y React repinta en vivostore/simulationStore.ts
14Al converger, finishRun guarda el resultado completostore/simulationStore.ts
15Las figuras y tablas leen del storecomponents/viz/*

Los pasos 7 a 11 se repiten hasta que el residuo baja de la tolerancia durante dos iteraciones consecutivas, o hasta agotar max_iter. Con el motor api los pasos 4-11 ocurren en el servidor y el 12 es un evento SSE.
